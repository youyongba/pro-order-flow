# 可见范围成交分布

`profile.js` 是不依赖 DOM 的共享计算模块，浏览器通过 `OrderFlowProfile` 使用，测试通过 CommonJS 加载。

| 方法 | 参数 | 返回 |
| --- | --- | --- |
| visibleIndices | K线数量、画布宽度、横向偏移、K线宽度 | `[开始索引, 结束索引)`；含边缘部分可见 K 线，扣除右侧价格轴 |
| aggregate | 可见 K 线数组，单根含 `cells: Map` | `Map<price, {buy, sell, total}>` |
| replaceCells | K 线对象、后端快照、Cell 构造函数 | 原地覆盖价位数据和完整性，不增量相加 |
| notification | 上次基线、时间范围标识、价位组合、是否允许 | 新基线和 `send`；范围改变不触发通知 |

```js
const [first, end] = OrderFlowProfile.visibleIndices(bars.length, 1200, 0, 80);
const profile = OrderFlowProfile.aggregate(bars.slice(first, end));
```

页面按后端历史接口恢复价位数据，实时每两秒覆盖最近两根 K 线。前台成交 WebSocket
仅维护即时价格与大单，不重复累计成交分布。历史浏览暂停前台数据更新，但后台采集继续。
时间范围和覆盖提示常驻面板；悬停可查看完整文字。数据量大时通过历史分页加载，图表缓存上限 1500 根。

每五秒对当前可见时间范围提交真实历史回补任务并轮询状态，历史浏览模式也刷新已回补的价位数据。
已结束分钟按后台校验结果逐步变成完整；当前分钟继续实时采集。失败显示具体原因与重试按钮。
回补快照是覆盖写入，不与旧分布相加；回补刷新会清除分布通知基线，避免产生历史变化告警。
每次打开页面生成独立 `clientId`，拖拽、缩放和切换周期时复用，后端用新范围替换该页面旧任务。
收到任务取消或排队繁忙 HTTP 429 时，页面退避 15 秒自动继续；币安本身限流仍明确提示并保留冷却。
后台每轮最多处理 5 分钟 / 6 次请求，优先新范围一轮后公平轮转；分页可跨轮继续。
进度区分准备、下载和分批轮转，只有已完成核验的分钟计入 X/Y，部分分页不计为完整。
校验不一致时显示拆分核验或自动重试。单分钟两次重试仍失败，终态 `partial` 显示已完成量和缺口数，并启用重试按钮。
`partial` 不自动无限轮询或重提任务；用户重试后跳过已完成分钟，仅处理剩余缺口。
