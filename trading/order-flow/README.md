# 持久化订单流

## 数据与约定

- 使用 Node 22，SQLite 文件固定为项目内 `data/order_flow.sqlite`，不读取交易密钥。
- 仅记录 Binance BTCUSDT 现货 `aggTrade`，固定 10 USDT 价格档位、1 分钟时间桶。
- `volume_cells` 保存主动买卖成交量，单位为 0.00000001 BTC 整数；查询时转为 BTC。
- `checkpoint` 与成交量在同一事务提交，保存最后成交 ID、时间和连续段起点。
- `coverage_segments` 记录成交 ID 连续的时间段。初次采集之前、ID 跳号之间不视为完整。
- 实时重复或迟到 ID 不累计；时间倒退的数据不接收。可见范围内的历史缺口自动提交回补任务。
- 历史使用币安公开 `aggTrades` REST，最多 5 个相邻缺失分钟合并请求、按 `fromId` 连续分页。
- 每分钟核对成交 ID、时间和数量，并与币安同分钟 K 线的总量及主动买量精确核对。
- 校验通过后事务替换该分钟，`backfilled_minutes` 保存验证标记；重复回补不叠加，不修改实时 checkpoint。
- 默认每秒批量提交。正常退出同步提交；强杀可能丢失最后未提交批次，下次收到跳号会标记缺口。
- 历史不自动删除。仅内存缓存有限；大单列表仍为本次进程内存数据。
- 历史成交分布不等于历史挂单墙，未归档的历史盘口不可恢复。

## REST 契约

`GET /api/auto-trade/orderflow/history`

| 参数 | 类型 | 默认值 / 约束 |
| --- | --- | --- |
| tf | string | `1m`；支持 `1m/5m/15m/60m/1h/4h/1d` |
| endTime | integer | 当前时间，毫秒；包含此时间所在 K 线 |
| limit | integer | 150；1 到 150 |

从 `endTime` 所在 K 线向前返回 `limit` 根，按时间升序。较早分页传最老 K 线开始时间减 1。
格式保留 `ok/data/largeOrders/largeOrderStats`，新增：

```json
{
  "ok": true,
  "data": [{
    "startTime": 1700000040000,
    "cells": {"60000": {"buyVol": 1.2, "sellVol": 0.3}},
    "totalDelta": 0.9,
    "coverage": "partial"
  }],
  "archive": {
    "market": "spot",
    "symbol": "BTCUSDT",
    "tickSize": 10,
    "lastAggId": 123,
    "lastTradeTime": 1700000045000
  },
  "largeOrders": [],
  "largeOrderStats": {"totalBuy": 0, "totalSell": 0}
}
```

`coverage` 为 `complete`（整个已结束时间桶连续覆盖）、`partial`（部分记录或尚未封闭时间桶）、
`missing`（无覆盖证据）。有效请求可返回空分布，不能将其解释为真实零成交。
非法参数返回 HTTP 400；归档读取失败返回 HTTP 503，不回退伪造数据。

### 历史回补任务

`POST /api/auto-trade/orderflow/backfill`

```json
{"startTime":1700000040000,"endTime":1700000640000,"clientId":"page_abc123"}
```

- JSON 整数毫秒，分钟对齐；范围 `[startTime, endTime)`。任务总跨度不再限制为 150 天，支持日线长视口。
- 起始时间仍须处于支持的历史范围内，不能请求未来时间；当前未收盘分钟不回补。不同参数错误分别返回具体原因。
- 不会一次加载整个范围的成交：每轮仍最多 5 分钟 / 6 次请求，保留队列上限、限速和旧视口取消机制。
- 最早允许 2017 年 7 月，实际可用历史取决于币安接口；不支持未来区间。
- 只处理已经结束的分钟，跳过已有完整记录，最新分钟优先。
- HTTP 202 返回 `{ok:true,job:{id,start,end,state,total,completed,trades,error,batches,batchMinutes,phase}}`。
- `GET /api/auto-trade/orderflow/backfill/:id` 查询进度。
- `clientId` 可选，1..64 位字母、数字、下划线或连字符；页面为每次打开生成独立 ID，切换周期时复用。
- 同一页面只保留最新范围；旧排队任务取消，运行中的旧任务在请求边界安全取消，未验证分钟不写入。
- `state` 为 `queued/running/complete/partial/failed/cancelled`；失败或取消均保留此前成功入库的分钟。
- 单进程串行请求，历史专用限速每 400ms 一次；429/418 后至少等待一分钟，显示失败而不无限重试。
- 新视口先获得一轮；与已有任务的公平轮次交替，不能被单个大范围一直阻塞，也不会让旧任务一直饥饿。
- 每轮最多 5 分钟 / 6 次上游请求，然后让出执行器。已下载但未完成的分页保留在内存，下轮从最后 ID 继续。
- `batches` 为已完成下载校验批次数；`phase` 为 `waiting/downloading/rotating/splitting/retrying/complete/partial`，终态以 `state` 为准。
- `completed` 只统计完整已有分钟或已经校验并入库的分钟，不能将下载了部分页数算作完成。
- 相邻分钟的 K 线一并获取，但仍逐分钟核对买卖量；全批次校验成功后逐分钟事务入库。
- 已完整分钟跳过并切开下载批次。每批最多 1000 页，超过安全上限明确失败。
- 买卖量不一致时，不放宽精度：多分钟批次先拆为单分钟，单分钟初次失败后分别等待 2 秒、5 秒再完整重下。
- 重试等待不占住执行器，其他任务照常轮转。校验成功才写入；每个单分钟最多初次请求 + 两次重试。
- 仍不一致的分钟保留为缺口并继续其他分钟，终态为 `partial`，不能当作全部完整。网络或非法数据等其他错误仍明确失败。
- `retries` 为自动重试次数，`skipped` 为持续校验失败分钟数，`completed + skipped = total`（到达部分完成终态时）。
- `lastMismatch` 与最近最多 20 个 `failures` 记录分钟时间、实际总量/买量及 K 线预期值，单位 0.00000001 BTC。
- 服务日志输出 `[orderFlowBackfill] Volume validation mismatch` 及同样的差异，便于区分偶发响应与持续数据不一致。
- 页面显示自动重试或剩余缺口，手动重试只会再请求未完整的分钟，成功分钟不会重复下载。
- 最多 8 个活跃任务、保留最近最多 32 个任务。同一页面相同非失败范围复用任务。
- 容量满时最新任务替换最旧的排队任务，不再因拖拽堆积直接返回队列已满。单线程上游并发仍为 1。
- 页面收到取消状态或兼容旧服务的 429 响应时，等待 15 秒自动继续，不停留在永久失败状态。
- 任务进度在内存，已回补数据在 SQLite；进程重启后页面重新发起，跳过已完成分钟。
- 尚未校验的分页进度在进程重启后重新下载，不能持久标记为完整。
- 无需 Binance API 密钥。代理只从启动终端环境变量读取。
- 使用固定币安 URL，不接受外部上游地址。与其它读写接口一样，应通过反向代理控制访问，不直接公开。

## 前端统计口径

按可见 K 线（包含两侧部分可见 K 线）的完整时间桶汇总成交分布。
价格轴仅裁剪绘制高度，不改变 vPOC/VAH/VAL 的统计范围。
实时聚合通过历史接口定期覆盖，不与浏览器 aggTrade 叠加。
历史浏览不更新实时 vPOC 快照、不发分布通知；返回实时先同步数据库并建立通知基线。
页面每五秒自动为可见范围提交任务或查询进度，并重新覆盖成交分布。
回补导致的价位变化仅建立通知基线，不作为实时行情信号推送。
历史跨度大时任务可能耗时很久，当前分钟会保持采集中；上游限制或数据不一致会明确提示失败。
页面区分「准备中 / 下载中 / 分批轮转中」，不存在无限并发或免限流模式。

## 备份

运行期间用 `npm run backup:orderflow -- /absolute/path/backup.sqlite` 创建 SQLite 一致性备份。
命令拒绝覆盖已有文件，不通过 HTTP 暴露备份能力。
建议定期备份到另一磁盘并监控数据库大小；不能在运行中仅复制 `.sqlite` 而忽略 WAL。
离线恢复：停止服务，确认已退出，把一致性备份放到 `data/order_flow.sqlite`，保留原库和配套
`-wal/-shm` 文件的停机备份，不要把旧 WAL 混入新库，再启动服务。
